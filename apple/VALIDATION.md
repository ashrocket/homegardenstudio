# Native phase-A verification

The standard native profile puts the plan canvas first, with a collapsible library and an inspector. Model changes go through the Rust bridge. Direct manipulation previews an engine transform and commits once; native UndoManager actions use engine history. Pinch zoom cancels a pending drag, and the inspector provides non-drag alternatives. Calibration offers both point selection and pixel-coordinate fields.

On 2026-11-01, the selected Xcode 26.6 toolchain built the universal macOS, iOS device and arm64 iOS Simulator Rust XCFramework. The macOS application and test bundle compiled, and all seventeen native unit tests passed, including the subsequent import atomicity and combined attachment-budget regressions. Coverage includes persistence, original-byte preservation, attachment corruption and limits, missing-original warnings, strict UTF-8/NUL handling before FFI, bridge responses and errors, repeated returned strings, native undo/redo, replacement history, units, free-plan access and URL titles. A focused arm64 iOS Simulator build also passed before the platform-neutral import fixes. Those fixes were then compiled and tested on macOS; the next integrated build will recheck both platforms. The owning Codex session retains separate logs for these checks.

The SwiftUI static audit reports no high-risk findings. Six medium observations cover canvas/width GeometryReaders, the library's bounded wide-window width, and index identities in stateless issue rows and the two fixed calibration-point slots. Three low observations require runtime gesture verification. The geometry readers are intentional drawing/adaptation boundaries. The library appears beside the canvas only with at least 850 points of available width and otherwise uses a sheet.

Provisional Apple Fidelity review: 76/100 (platform 12/15, layout 11/15, native semantics 13/15, interaction 15/20, motion/material 11/15, accessibility 6/10, implementation/performance 8/10). This is a code/build assessment capped below runtime acceptance. It is not a claim that the UI passed the skill's hard gates or the 90-point target.

Still required: native interaction and screenshot matrix on Mac, iPhone and iPad; actual document save/reopen and library drag/drop; rapid/cancelled gestures; narrow layouts and large type; VoiceOver and keyboard-only use; appearance/contrast and reduced effects; performance sampling for large plans. Unit-test execution launched the host application but does not establish these user-flow outcomes.
